# 方案 · 点击穿透（E11）

> **对应待办**：E11 —— 桌宠当前会遮挡下层 UI，鼠标点击落在透明区域也被猫吃掉
> **机制来源**：MeaPet `meapet/desktop/click_through.py`（MIT）Win32 段阅读改写，**未复制代码文本**
> **状态**：设计完成，**未实施**（代码中目前不存在 `setMask` / `WS_EX_TRANSPARENT`）

---

## 一、问题定义

`ui/floating_pet.py` 是 `Qt.FramelessWindowHint | Qt.WindowStaysOnTopHint | Qt.WA_TranslucentBackground` 的透明窗口，尺寸固定 `256×256`（`_display_size`）。猫咪只占其中一部分，但**整个矩形窗口都在吃鼠标事件** —— 猫身后的按钮、输入框点不到。

---

## 二、MeaPet 的做法（Win32 段，约 100 行）

```python
previous = GetWindowLongW(hwnd, GWL_EXSTYLE)
new_style = previous | WS_EX_LAYERED | WS_EX_TRANSPARENT
SetWindowLongW(hwnd, GWL_EXSTYLE, new_style)      # 关闭时原样还原 previous
```

三个要点：

1. **必须保存 `previous_exstyle` 并原样还原** —— 反复开关若不做还原会累积脏位，最终表现是"关不干净"。
2. **穿透后窗口收不到鼠标事件**，因此它用 `GetAsyncKeyState(VK_RBUTTON) & 0x8000` **轮询物理右键**判断"用户想操作我"，配合 `RightClickEdgeDetector.update(cursor_in_pet, button_down)` 做边沿检测（`False → True` 才算一次按下）。这是穿透模式下的通用手法。
3. **源码注释点明了工业标准**：

   > for per-pixel hit testing (dynamic silhouette), subclass WndProc and handle WM_NCHITTEST — return HTTRANSPARENT for transparent pixels, HTCAPTION for the draggable body. This is the industrial-standard approach for Live2D pets on Windows.

另外 `set_shape_region(state, rects)` 只在 **X11 / Wayland** 后端生效，**Win32 分支没有实现**（调用返回 `False`）—— 说明在 Windows 上做动态命中区性价比不高。

## 三、路线对比

| | 路线 A：整窗穿透 + 右键守卫 | 路线 B：`WM_NCHITTEST` 逐像素命中 |
|---|---|---|
| 原理 | 加 `WS_EX_TRANSPARENT`，鼠标全部下传 | 子类化窗口过程，命中判定按帧位图 alpha 决定返回值 |
| 效果 | 猫**全身**都不响应鼠标（含可见部位） | 透明区穿透、猫身可点可拖 —— 理想的"轮廓裁剪" |
| 工作量 | 约 1 小时 | 约 1 天，需 ctypes 子类化 WndProc，风险更高 |
| 对现有交互的破坏 | 会失去"点击/拖拽猫"能力，需靠右键守卫兜底 | 无 |
| 建议 | ✅ **先落地**，解决"挡住下层 UI"的核心痛点 | 排后，作为体验升级 |

### ⚠️ 为什么不能用 `QWidget.setMask(QRegion)`

待办清单里 E11 写的是"`setMask` 基于帧轮廓裁剪"，但**这条路走不通**：Windows 上 `setMask()` 会同时裁剪**绘制与命中** —— 用帧轮廓当掩码会把猫咪本体直接切掉（不可见），而且它无法表达 `HTTRANSPARENT`（"让事件穿透到下层"）的语义，只能做到"这个窗口不接受输入"。**正确的实现是路线 B，不是 `setMask`。**

## 四、路线 A 落地要点

| 步骤 | 要点 |
|---|---|
| 取句柄 | `int(widget.winId())`（需窗口已创建原生句柄） |
| 加样式 | `GWL_EXSTYLE(-20)` 读 → `\|= WS_EX_LAYERED(0x00080000) \| WS_EX_TRANSPARENT(0x00000020)` → 写回 |
| **强制刷新** | 改完必须 `SetWindowPos(hwnd, 0,0,0,0,0, SWP_NOMOVE\|SWP_NOSIZE\|SWP_NOZORDER\|SWP_NOACTIVATE\|SWP_FRAMECHANGED)`，否则偶发不生效 |
| 右键守卫 | `QTimer` 30ms 轮询 `GetAsyncKeyState(VK_RBUTTON) & 0x8000`；检测到按下 → 摘掉透明样式；抬起后延迟约 800ms 再恢复（否则吞掉右键菜单的点击） |
| 还原 | `disable()` 时写回保存的 `previous_exstyle`；程序退出路径必须调用 |
| 入口 | 托盘菜单加"点击穿透"开关；设置项可选 |

**注意**：进入穿透后，`ui/chat_bubble` 与 `notification_bubble` 是**独立窗口**，不受影响 —— 它们仍需正常接收鼠标。因此穿透**只作用于 `FloatingPet` 这一个窗口**，不要全局套用。

---

## 五、路线 B 落地要点（后续）

1. `SetWindowLongPtrW(hwnd, GWLP_WNDPROC, new_proc)` 子类化，保存原过程；
2. 在 `WM_NCHITTEST` 中把屏幕坐标换算到窗口局部坐标；
3. 查帧位图 alpha（**可复用 `floating_pet.py` 中已经算好的 `mask`**：`pix.createMaskFromColor(Qt.transparent, Qt.MaskOutColor)`）：
   - alpha < 阈值 → `return HTTRANSPARENT`（穿透）
   - 落在猫身 → `return HTCAPTION`（可拖拽）/ `HTCLIENT`
4. 换情绪时同步更新掩码；
5. 退出时 `SetWindowLongPtrW` 还原原过程，否则窗口销毁会崩。

## 六、验证方法

| 验证点 | 方法 |
|---|---|
| 穿透是否生效 | **鼠标悬停在猫身上滚滑轮，看下层窗口（如浏览器）是否滚动** —— 比看代码可靠 |
| 样式是否刷新 | 切换开关后立刻测试（`SWP_FRAMECHANGED` 是否漏加会在这里暴露） |
| 右键菜单可达 | 穿透状态下按右键 → 菜单应能弹出且可点击 |
| 退出是否还原 | 关闭程序后重启，确认鼠标行为正常（构造函数每次重读 `previous_exstyle`，可自愈残留） |
| 不误伤其他窗口 | 确认 `chat_bubble`、`notification_bubble` 仍可点击输入 |

## 七、风险

| 风险 | 说明 | 处置 |
|---|---|---|
| 穿透后无法点击/拖拽猫 | 路线 A 的固有代价 | 用右键守卫 + 托盘开关兜底；若体验不可接受再上路线 B |
| `winId()` 取过早 | 句柄无效导致设置失败 | 在窗口 `show()` 之后再启用；失败要 logger 记录而非静默 |
| 右键轮询开销 | 30ms 一次 `GetAsyncKeyState` | 开销可忽略；仅在穿透启用时轮询 |
| 多屏/DPI 缩放 | 坐标换算（路线 B 才会遇到） | 路线 A 不涉及 |
