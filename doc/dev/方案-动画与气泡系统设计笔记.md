## 一、卡点定位

| 事实 | 含义 |
|---|---|
| 当前动画 = 逐帧 SVG 序列（`ui/floating_pet.py`，8 个情绪目录） | 每个情绪需要成套帧图 |
| AI 生成的帧**不可控**（风格/比例/连贯性不稳） | 无法保证产出可用，返工成本高 |
| **没有美术时间投入** | 依赖"做素材"的方案一律不可行 |
| `dev/方案-Lottie动画迁移.md` 要求 AE 制作 7 个 Lottie JSON | 该方案自身已判定："核心瓶颈在第二步（需要 AE 技能），走不通" |

**结论：动画必须从"美术资产问题"转成"程序问题"。** 即：要么用**现成模型**（Live2D），要么用**代码驱动的形变**（部件化）。

---

## 二、三条路线对比

| 路线 | 依赖美术？ | 可控性 | 时间成本 | 评价 |
|---|---|---|---|---|
| Lottie（AE 制作 JSON） | 必须（AE 或动画师） | 低 | 2–3 天且不可控 | ❌ 放弃 |
| **Live2D 现成模型 + `live2d-py`** | 不需要 | **高**（动作/表情/物理/眨眼全由模型自带） | 1 天接入 | ✅ **主路线**（有未验证前提，见 §四） |
| **SVG 部件化 + 程序驱动** | 不需要 | 高（自己写形变规则） | 半天 | ✅ **保底/兜底**，当天见效 |

## 三、保底方案：SVG 部件化程序动画（纯代码、零美术）

把现有像素猫拆成 `body / ears / tail / eyes` 四层，用 `QPropertyAnimation` + `QTimer` 程序化驱动：

| 微动作 | 实现 | 对应待办 |
|---|---|---|
| 呼吸起伏 | `scaleY` 0.98 ↔ 1.02 往复 | P2-1 |
| 眨眼 | 眼睛层显隐约 80ms，随机间隔 | P2-1 |
| 尾巴摆动 | 尾部层旋转 ±8° | P2-1 |
| 耳朵抖动 | 耳部层小幅旋转 | P2-1 |
| 鼠标视线跟随 | 整层 ±3px 位移跟随鼠标 | P2-2 |
| 抚摸反馈 | hover > 2s → 切 `happy` + 气泡"呼噜呼噜~" | P2-3 |

**优点**：不引入新依赖、不碰 OpenGL、当天可跑；**缺点**：表现力上限低（不如 Live2D 鲜活）。

## 四、主路线：Live2D + `live2d-py`（**有一个未验证前提**）

### 4.1 为什么它能一次解决两个卡点

`live2d-py`（`EasyLive2D/live2d-py`）是 Live2D Native SDK 的 **Python C 扩展封装**，**不经过 Web 引擎**，官方声明兼容 `PyQt5 / PySide6 / Pygame / GLFW` 等一切 OpenGL 窗口。已支持：

- 模型加载（Cubism 2.1 / 3.0+）
- **视线跟踪**（P2-2 直接满足）
- **点击交互 + 精确到部件的点击检测**（与 E11 的逐像素命中同源）
- **动作播放回调**（状态机挂钩）
- 口型同步、部件参数与透明度控制

即：**"动画不可控"和"交互命中判定"两个卡点都是模型/库现成的**，Vel 只需写"状态 → 动作名"的映射。

### 4.2 现成范例

- `EasyLive2D/Live2DMascot` —— Python + live2d-py 的**桌面 Live2D**，含聊天接口。比读文档快，直接看它 `main.py` 如何把模型挂到窗口上。
- 模型素材：先用 Cubism 官方示例模型（`Haru` / `Hiyori` / `mao_pro`）跑通链路。

### 4.3 ⚠️ 未验证前提与风险

| 项 | 说明 |
|---|---|
| **透明窗口 + OpenGL** | live2d-py 走 OpenGL，需 `QOpenGLWidget` 承载；与 `Qt.WA_TranslucentBackground` 的无边框透明窗口叠加**可能出现黑底/闪烁**。这是唯一需要花时间调的点，**建议先写 30 分钟独立小脚本验证"透明窗口 + QOpenGLWidget + 模型能显示"，通过后再动 `floating_pet.py`** |
| **素材许可** | Cubism Core/Framework 受 Live2D 官方许可约束；**官方示例模型仅限学习/个人用途，商用需授权**；Live2D SDK 另有营收门槛条款。Vel 现状是"个人内测自用"，风险可控；若将来分发必须重新确认 |
| **形象一致性** | 若 Vel 的角色必须是"猫"，二次元人形模型不合适 —— **此时应直接走 §三 的保底方案，不引入 OpenGL 复杂度** |

## 五、DyberPet 的可迁移设计（零美术、纯代码）

DyberPet 是 992★ 的 PySide6 桌宠，**它的动画素材同样是"帧序列 + JSON 配置"**，印证了第二节的判断：成熟桌宠不要求美术做 Lottie。

### 5.1 动画配置化（`res/role/<pet>/pet_conf.json`）

```json
{
  "width": 98, "height": 98, "scale": 1.0,
  "refresh": 5, "interact_speed": 0.02,
  "default": "default", "up": "up", "down": "down",
  "left": "left", "right": "right", "drag": "drag",
  "fall": "fall", "on_floor": "onfloor",
  "random_act": [
    {"name": "站立",     "act_list": ["default"],                     "act_prob": 1.0,  "act_type": [2, 0]},
    {"name": "左右行走", "act_list": ["left_walk", "right_walk", "default"], "act_prob": 0.1, "act_type": [3, 1]},
    {"name": "生气",     "act_list": ["angry"],                       "act_prob": 1.0,  "act_type": [0, 0]},
    {"name": "睡觉",     "act_list": ["fall_asleep", "sleep"],        "act_prob": 0.05, "act_type": [1, 1]},
    {"name": "onfloor",  "act_list": ["onfloor"],                     "act_prob": 0,    "act_type": [0, 10000]}
  ]
}
```

**要点**：

- `act_prob` 是**权重**（`random.choices` 抽签），不是概率阈值 —— `睡觉 0.05` 意味着很少被选中；
- `act_list` 支持**多帧序列**（`fall_asleep → sleep` 是两段衔接），Vel 现有 `set_emotion(act, loop=False, after="idle")` 已支持该语义；
- `act_type: [a, b]` 是该动作的可中断/可循环一类的开关（`[0, 10000]` 那个近乎禁用，因为由物理触发）；
- **换角色 = 换一个 JSON，代码零改动** —— 这是它被 fork 105 次的根本原因。

> Vel 的 `ui/floating_pet.py:103` 目前把 8 个情绪名**硬编码在元组里**，应改为读取此类 JSON。

### 5.3 气泡系统（`bubbleManager.py`，210 行）—— 六个可迁移机制

配置形态（`res/icons/bubble_conf.json`）：

```json
{
  "pat_focus":     {"icon": "bb_pat_focus", "message": "USERTAG You should be focusing on your work",
                    "countdown": null, "start_audio": null, "end_audio": null},
  "feed_required": {"icon": null, "message": "USERTAG I want to have ITEMNAME",
                    "countdown": 120, "start_audio": null, "end_audio": null}
}
```

| # | 机制 | 价值 |
|---|---|---|
| 1 | **双层配置合并**：系统默认 + `res/role/<pet>/note/bubble_conf.json` 覆盖，逐键 `update()`，角色还能**新增**键 | 解决"角色资源"与"系统配置"耦合 |
| 2 | **按状态分档触发**：`bubble_hp_tier = {0: [...], 1: [...], 2: [...]}`，从当前档位 `random.choice` | 健康模块（饿/渴/久坐）可直接同构 |
| 3 | **占位符替换**：`USERTAG`（昵称）、`ITEMNAME`（随机道具，且排除 dislike 与负效果道具），替换后 `re.sub(r'\s{2,}', ' ', msg)` 清多余空格 | 与 `prompt_builder` 的 `{user_name}` 统一 |
| 4 | **可扩展随机类型**：任何 `pat_random_*` 键都会被收集为候选 | **加气泡不改代码** |
| 5 | **同类去重 + 冷却**：`bubble_type` 取前两段（`pat_random_1` → `pat_random`）避免刷屏 | Vel 目前单通道气泡，P2 的气泡会与对话抢位 |
| 6 | **`countdown`**：配置即渲染倒计时 | "该喝水了"这类需持续可见的提醒可复用 |

**建议**：把 P2 的微动作反馈（"呼噜呼噜~"）走**系统气泡通道**，不要挤进对话历史（`ui/chat_bubble.py` 是对话气泡，语义不同）。
