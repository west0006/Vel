# 规格 · 重做动画帧序列

> **用途**：给 AI 生图流程（或画师）一套明确规格，产出**时序一致**的帧序列，从根上解决帧间跳变。
> **背景依据**：诊断数据见 `计划-当前待办.md` §3.0 —— 现有帧的帧间内容差异 75~98%、面积差异最高 2.10x、底边跳动 36px。
> **交付方式**：素材放入 `ui/resources/animations/pet_svg/<情绪>/` 即生效，**无需改任何代码**。

---

## 一、为什么必须重做（诊断依据）

| 情绪 | 帧数 | 主题宽变化 | 底边变化 | 平移对齐后残余差异 |
|---|---|---|---|---|
| sleep | 2 | **123~231px（近 2 倍）** | 199~223 | 93.8% |
| sad | 4 | 175~215px | 211~227 | **98.3%** |
| wake | 8 | 135~227px | 199~239 | 89.8% |
| happy | 4 | 155~231px | 223~243 | 85.1% |
| idle | 6 | 147~191px | 235~243 | 75.4% |

**关键结论**：把相邻帧做最佳平移对齐后，差异仍残留 75~98% —— 说明帧间差异**主要不是位移，而是图像内容本身不同**（每帧的猫"长得不一样"）。这是 AI **逐帧独立生成**的典型症状。

代码侧的归一化（已完成）只能统一尺寸、对齐底部，**无法让不同形状的猫变得连续**。所以根治必须重做素材。

## 二、硬性规格

### 2.1 画布与格式

| 项 | 要求 |
|---|---|
| 画布 | **512×512**（与代码常量 `FRAME_RENDER_SIZE` 一致）；256×256 也可 |
| 背景 | **完全透明**（alpha=0），不要白底、不要背景元素 |
| 格式 | SVG（像素画，由 `<rect>` 拼成，与现有素材一致）或 PNG 序列 |
| 命名 | `<情绪>_<两位序号>.svg`，如 `idle_01.svg`，序号从 01 起连续 |
| 目录 | `ui/resources/animations/pet_svg/<情绪>/` |
| 情绪名 | **固定 8 个**：`idle` · `wake` · `thinking` · `sleep` · `sad` · `happy` · `alert` · `collapsed` |

### 2.2 时序一致性（最关键，可自动化检验）

| 指标 | 阈值 | 含义 |
|---|---|---|
| 主题高度离散 | ≤ 5%（极差/均值） | 猫的大小不能变 |
| 主题面积离散 | ≤ 15% | 视觉大小 |
| **底边极差** | **≤ 3px** | 脚的位置不能跳 |
| 水平重心极差 | ≤ 5px | 不能左右漂 |
| 每情绪帧数 | **≥ 8** | 现有 2~8 帧太少，循环生硬 |
| 首尾衔接 | 循环播放不跳 | 首尾帧差异 ≈ 相邻帧差异 |

### 2.3 内容要求

1. **同一情绪内的帧必须是同一姿态的连续微小变化**（呼吸起伏、尾巴摆动、眨眼），
   **不要在两帧之间切换姿态** —— 现有 `sleep` 只有 2 帧、一帧蜷缩一帧竖立，是最典型的反例。
2. 相邻帧的差异应"渐进"，不能"跳跃"。
3. 风格统一：描边粗细、配色、像素密度一致。
4. 建议帧率 8~12 fps，循环周期 1.5~3 秒。

### 2.4 各情绪的动作建议

| 情绪 | 建议动作（保持姿态不变，只做小幅变化） |
|---|---|
| `idle` | 呼吸起伏（胸腹微动）+ 尾巴慢摆 |
| `wake` | 睁眼 → 伸懒腰 → 坐起（**渐进序列**，非跳跃） |
| `thinking` | 歪头 + 耳朵转向 |
| `sleep` | 保持同一蜷缩姿态，只做缓慢呼吸 |
| `sad` | 低头 + 耳朵下垂 |
| `happy` | 小跳（整体位移渐变）+ 尾巴快摆 |
| `alert` | 竖耳 + 身体绷紧（幅度要小） |
| `collapsed` | 趴平 + 微弱呼吸 |

## 三、生成方法（推荐 A）

### 方法 A：img2img 链式微调 ⭐ 推荐

1. 先生成**基准帧**（如 `idle_01.svg`），定下形象与配色；
2. 以基准帧为输入做 img2img（denoise 强度 **0.15~0.3**），prompt 描述"同一只猫的微小姿态变化"；
3. **以上一帧为输入**继续生成下一帧（链式），保证连续性；
4. **每 3~4 帧回锚到基准帧**，避免误差累积导致整体漂移。

> 关键：不要每帧都从零生成（那正是当前问题的成因）。

### 方法 B：sprite sheet 一次生成

一次生成包含全部帧的整张图，prompt 示例：

```
sprite sheet, 8 frames, pixel art orange cat breathing,
identical size and position in each cell, evenly spaced grid,
transparent background, no text, no border
```

生成后按网格切帧。

- 优点：一次出全套，风格天然统一；
- 缺点：模型对"帧间一致性"的控制不稳定，可能需要多次尝试。

### 方法 C：单图 + 程序变形（零素材工作量）

只生成**一张透明底**的高质量猫图，动画全部由代码完成（呼吸 / 缩放 / 摇摆 / 位移 / 特效）。

- 优点：**彻底消除帧间不一致**（只有一张图）；
- 缺点：无法表达"换姿势"类动作（如坐下→站起）。

> ⚠️ 现有 `ui/resources/animations/cat_1.png`（1024×1024）经检测 **100% 不透明（带背景）**，
> 不能直接用于方法 C，需先抠图或用 AI 重新生成透明底版本。

## 四、生成后自检（必做）

仓库自带体检工具：

```bash
python -m tools.check_anim_frames           # 检查全部情绪
python -m tools.check_anim_frames idle sleep  # 只检查指定情绪
```

输出每个情绪的高度/面积离散度、底边与重心极差，并给出 **PASS / FAIL** 判定（阈值即 §2.2）。

> 当前素材的运行结果是 **全部 FAIL** —— 可用它对照改进效果。

---

## 五、替换与验收

1. 素材放入对应情绪目录（替换或新增文件）；
2. 跑体检工具 → 目标情绪全部 **PASS**；
3. 跑 `python -m pytest tests -q`（含 `tests/unit/test_frame_norm.py` 的归一化断言）；
4. 跑 `python main.py` **肉眼确认**循环是否顺滑（这一步不可省，工具只能量化一致性）；
5. 若帧数变化较大，检查 `ui/resources/pet_conf.json` 的微动作配置仍指向有效情绪名。
