# 计划-R1 · ChatManager 记忆服务晚绑定

> **状态**：✅ 完成 ｜ **最后核对**：2026-11-10
> **来源**：2026-11-10 真机日志 —— `chat_manager` 初始化早于 `memory_service` 注册

## 问题

`main.py` 用后台线程加载 `MemoryService`（`_init_memory`），而 `ChatManager.initialize()` 紧接着在主线程执行，只 `registry.get("memory_service")` 一次。模型加载通常需要数秒，因此 `ChatManager._memory_service` 很可能永久为 `None` → 记忆召回与摘要写入在本进程内不生效。

## 目标

- 把 `_memory_service` 改为**惰性获取**：首次使用时重试，拿到后缓存。
- `initialize()` 时仍做一次尝试；失败不抛异常。
- `_retrieve_memories()` 无服务时返回 `[]`；`_trigger_summary()` 无服务时跳过写入。
- 不改变已有启动顺序、不阻塞 UI、不修改 `MemoryService`。

## 非目标

- 不改 `MemoryService` 的初始化方式或线程模型。
- 不改全屏判定导致 `active → busy / companion → silent` 的行为。
- 不改 `mood_logger` 未注册（EMO-1 / V0018）。
- 不提交。

## 验收标准

- [x] 无 `memory_service` 时 `initialize()` 不抛异常，`_get_memory_service()` 返回 `None`。
- [x] 服务在 `initialize()` 之后注册时，下一次 `_retrieve_memories()` 能拿到并调用 `search()`。
- [x] 成功获取后缓存；后续调用不再依赖 `registry.get`。
- [x] `_trigger_summary()` 在晚注册后能调用 `add_memory()`。
- [x] 新增单测覆盖以上行为；全量回归全绿。

## 步骤

1. `modules/chat/chat_manager.py` 新增 `_get_memory_service()`。
2. `_retrieve_memories()` / `_trigger_summary()` 改用该方法。
3. 新增 `tests/unit/test_chat_memory_late_bind.py`。
4. 全量回归、`git diff --check`。

## 风险与回滚

| 风险 | 处置 |
|---|---|
| 首次消息早于服务注册 | 本次返回空记忆，下次消息自动重试 |
| 服务永久不可用 | 每次消息多一次 `registry.get`（字典查找，成本可忽略） |
| 缓存后服务被替换 | 与现有行为一致；本任务不处理热替换 |
| 回滚 | 只改 `chat_manager.py` 与新增测试，可单独 revert |
