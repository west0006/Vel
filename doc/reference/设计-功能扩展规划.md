### 0. 总体架构调整

新增功能均遵循现有分层架构，不引入新框架：

```
UI层 (PyQt5)       ←→  业务逻辑层 (modules/)   ←→  服务层 (services/)  ←→  数据层
     ↑                         ↑
  事件总线 (EventBus)  ← 发布/订阅
```

- **UI层新增/修改**：对话气泡工具栏、通知气泡扩展、设置面板新增页、养成商店界面。
- **业务逻辑层新增模块**：`modules/greeting.py`, `modules/diary.py`, `modules/memo.py`, `modules/pomodoro.py`, `modules/habit.py`, `modules/feeding.py`。
- **服务层变更**：现有 `search_service` 被问候功能调用获取天气；`mood_logger` 提供情绪数据；`reminder_scheduler` 管理新提醒类型。
- **数据库新增表**：`daily_diary`, `memo`, `habit`, `unlockables`；`app_settings` 新增 `cat_food` 键。
- **事件总线新增事件**：`DIARY_GENERATED`, `HABIT_REMINDER`, `MEMO_REMINDER`, `POMODORO_START/END`, `CAT_FOOD_CHANGED`, `GREETING_TRIGGERED`。

### 1. 智能问候

#### 1.1 触发条件
- 每日首次唤醒桌宠（通过点击或热键呼出对话气泡）。
- 系统从睡眠/锁屏恢复后第一次唤醒（可选，需检测系统事件）。
- 用户主动说“早上好”或类似语句时，强制触发一次。

#### 1.2 交互流程
1. 用户唤醒桌宠（点击或按 `Ctrl+Shift+C`）。
2. 系统检查今日是否已问候（`app_settings` 中 `last_greeting_date` 是否为今天）。若否，进入问候流程。
3. 问候模块收集上下文：当前时段（早/中/晚）、天气（通过搜索服务获取）、最近情绪（昨日最后一条 `mood_snapshot`）、用户昵称。
4. 调用 LLM 生成问候语（最多50字），例如“早上好，小名！今天会下雨，出门记得带伞，昨天你看起来有点累，今天多喝水喵~”。
5. 通知管理器将此问候作为**特殊通知**插队到队列最前，显示在猫咪头顶的通知气泡中，3秒自动消失（不可手动关闭，不可小睡）。
6. 若此时对话气泡已经打开，则不弹出通知气泡，而是在对话历史中直接显示为桌宠的第一条消息。
7. 记录 `last_greeting_date = today`。

#### 1.3 UI呈现
- 通知气泡样式：左侧一个像素太阳/云朵图标（根据天气动态切换），文字使用加粗14px，颜色 `#1E1E1E`，背景 `#FAFAFA`，边框强调色 `#FF6B35`。
- 无操作按钮，仅有文本，3秒后自动消失并触发猫咪 `wake` 动画。

#### 1.4 数据与服务依赖
- `user_profile` 获取昵称。
- `search_service.search_weather()` 获取天气简短描述（需缓存）。
- `mood_logger.get_last_mood()` 获取昨日最后情绪标签。
- `llm_service.generate(prompt)` 生成问候语。

#### 1.5 事件
- 发布 `GREETING_TRIGGERED` 事件，携带问候语文本，通知管理器订阅并显示。

### 2. 猫咪日记

#### 2.1 触发与生成
- **自动生成**：每日21:00，由 APScheduler 触发 `diary.generate_daily()`。
- **手动生成**：用户对桌宠说“写日记”或“今天的日记”，可强制生成今日日记（幂等，一天一份）。

#### 2.2 生成逻辑
1. 聚合当日数据：
   - 日程：从 `schedule` 统计 `status='completed'` 的数量和标题。
   - 饮水：从 `drink_log` 汇总总量，对比日目标。
   - 活动：从 `activity_log` 统计完成次数。
   - 饮食：从 `meal_log` 获取午餐、晚餐内容。
   - 情绪：从 `mood_snapshot` 获取当日主导情绪。
2. 拼接提示词，调用 LLM 生成一段话（50-100字），语气温馨，带 emoji。
3. 存入 `daily_diary` 表，如果当日记录已存在则更新。
4. 自动生成后，通过事件通知用户（可选，默认不弹通知，只在用户主动查看时显示；也可配置为生成后弹一个轻提示“今天日记已生成”）。

#### 2.3 查询日记
- 用户可通过对话触发查询：“昨天的日记”、“看看日记”。对话管理模块识别意图，从数据库读取 `summary` 并回复。
- 设置面板“数据”页增加“查看日记”按钮，打开一个只读列表窗口，显示历史日记（日期+摘要），可点击查看全文。

#### 2.4 UI
- 日记查询结果在对话气泡中直接显示，格式为日期标题 + 文本内容。
- 独立日记窗口（从设置面板进入）：扁平列表，每项左侧日期，右侧摘要缩略，点击展开全文。

#### 2.5 数据库
```sql
CREATE TABLE daily_diary (
    date DATE PRIMARY KEY,
    summary TEXT NOT NULL,
    generated_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

#### 2.6 事件
- `DIARY_GENERATED`：携带日期和摘要，可用于通知管理器提示用户（可选）。

### 3. 隐藏彩蛋

#### 3.1 功能概述
在对话中预设若干关键词或短语，当用户消息精确或模糊匹配到关键词时，触发特殊的猫咪动画和俏皮回复，增加趣味性。

#### 3.2 触发条件
- 用户输入文本（对话气泡）**完全匹配**或**包含**关键词列表中的某一项。
- 关键词分两类：
  - **精确匹配**（如“喵喵喵”、“你好呀”）——大小写不敏感，忽略首尾空格。
  - **语义匹配**（如“讲个笑话”、“今天心情真好”）——通过简单正则或子串检测。

#### 3.3 彩蛋内容定义
存储于 `config/easter_eggs.yaml`，结构示例：
```yaml
eggs:
  - trigger: "喵喵喵"
    type: exact
    animation: "special_happy"   # 自定义动画状态
    reply: "喵～ 你终于说猫话了！"
  - trigger: "秘密"
    type: contains
    animation: "surprised"      # 需新增或复用 alert 状态
    reply: "嘘……被发现了喵。"
  - trigger: "讲个笑话"
    type: contains
    animation: "happy"
    reply: "为什么猫咪不喜欢上网课？因为鼠标太诱人了！"
```

#### 3.4 交互流程
1. 用户发送消息 → 对话管理模块 `ChatManager.process_message(text)`。
2. **优先检查彩蛋**：遍历彩蛋列表，匹配规则。
3. 若命中：
   - 跳过 LLM 调用。
   - 直接返回预设回复文本。
   - 通过 `EventBus.publish("PLAY_SPECIAL_ANIMATION", {"animation": egg.animation})` 触发动画控制器播放对应帧序列。
   - 动画播放完毕后返回 `idle` 状态。
4. 若未命中，走正常 LLM 对话流程。

#### 3.5 UI
- 无额外UI，彩蛋回复在对话气泡中以标准桌宠消息样式显示。
- 触发特殊动画时，猫咪可能做转圈、跳起等动作（需美术提供对应像素帧）。

#### 3.6 新增/修改模块
- 新建 `modules/easter_egg.py`：负责加载 YAML 配置、匹配检测。
- 修改 `modules/chat/chat_manager.py`：在 `process_message` 开头插入彩蛋检查。
- 修改 `ui/animation_controller.py`：添加 `special_happy`、`surprised` 等新状态。

#### 3.7 事件
- `PLAY_SPECIAL_ANIMATION`（新增）：携带动画名称，动画控制器订阅。

### 4. 简易备忘录

#### 4.1 功能概述
支持语音或文字输入：“记一下：明天上午10点打电话给医生”，系统解析出内容和提醒时间，存入备忘录表，到期时通过轻量通知提醒。

#### 4.2 与日程的区别
- 备忘录无严格结束时间，仅一个提醒时间。
- 提醒级别为“低优先级”，排在日程预警之后、健康提醒之前。
- 支持直接标记完成，无小睡机制，过期未标记自动视为“错过”。

#### 4.3 触发条件
- 用户在对话中输入以“记一下：”或“备忘录：”开头的语句，或说出类似意图（由 LLM 判断）。
- 也可以在对话气泡工具栏中点击“备忘录”图标，直接打开创建窗口。

#### 4.4 交互流程

**创建备忘录**
1. 用户输入：“记一下：后天下午3点约见客户”。
2. `MemoParser` 解析：
   - 提取时间表达式 `后天下午3点` → 转换为具体 datetime。
   - 提取内容：“约见客户”。
   - 若无法解析时间，询问用户补充，或作为无提醒的普通记事保存。
3. 生成确认：“已记录备忘录：后天下午3点 约见客户”，附带【查看】【撤销】按钮。
4. 存入 `memo` 表。

**提醒触发**
1. APScheduler 在 `remind_at` 时间触发备忘录提醒。
2. `NotificationManager` 接收 `MEMO_REMINDER` 事件，队列优先级低于 `SCHEDULE_ALERT`，高于 `HEALTH_REMINDER`。
3. 猫咪做轻微提醒动作（如歪头），弹出轻量通知气泡：
   - 标题：“备忘录”
   - 内容：具体事项
   - 按钮：【完成】【忽略】
4. 用户点击“完成” → `status='completed'`；点击“忽略” → 标记 `status='missed'`。

**查看与管理**
- 对话中询问“我的备忘录” → 从数据库读取所有 `active` 备忘录，列表显示。
- 设置面板新增“备忘录”导航项，列表展示所有备忘录，支持编辑、删除、手动完成。

#### 4.5 UI

**通知气泡**：
- 宽度 280px，背景 `#FAFAFA`，左边框 `3px solid #5A5A5A`（灰色以区分日程和健康），圆角 10px。
- 左侧图标：小记事本线条图标。

**对话中查询结果**：
- 以简洁列表形式显示在聊天历史中，每项格式：“📌 明天15:00 约见客户 [完成] [删除]”。

**设置面板-备忘录页**：
- 顶部搜索框（筛选内容）。
- 列表显示所有备忘录（按时间排序），每行：状态图标、时间、内容摘要、操作按钮（完成/删除）。

#### 4.6 数据库
```sql
CREATE TABLE memo (
    id TEXT PRIMARY KEY,
    content TEXT NOT NULL,
    remind_at DATETIME,
    status TEXT DEFAULT 'active',  -- active, completed, missed
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

#### 4.7 新增/修改模块
- `modules/memo.py`：MemoManager（解析、存储、查询）。
- `services/reminder_scheduler.py`：注册备忘录类型任务。
- `ui/settings_window.py`：增加备忘录管理页。
- `ui/chat_bubble.py`：增加工具栏按钮（备忘录图标）及快速创建对话框。

#### 4.8 事件
- `MEMO_CREATED`：携带 memo_id，用于通知动画“记录成功”。
- `MEMO_REMINDER`：携带 memo 对象，由 NotificationManager 订阅。

### 5. 番茄钟定制

#### 5.1 功能概述
内置番茄钟，支持自定义专注/休息时长，与久坐检测联动。专注期间不计入久坐计时，结束时触发活动提醒。

#### 5.2 触发与使用方式
- **启动**：对话气泡输入框上方工具栏点击“番茄”图标，或输入指令“开始番茄钟”。
- **快捷操作**：支持快捷键 `Ctrl+Shift+T` 启动/暂停。
- **暂停/恢复**：点击工具栏按钮或快捷键。
- **取消**：长按按钮2秒或输入“取消番茄钟”。

#### 5.3 交互流程

**配置（设置面板-健康页）**
- 专注时长滑块：默认 25 分钟，范围 15-60 分钟。
- 休息时长滑块：默认 5 分钟，范围 2-15 分钟。
- 长休息间隔：每完成 4 个番茄钟后，自动触发长休息（默认 15 分钟）。

**运行中**
1. 用户启动番茄钟 → `PomodoroManager` 开始倒计时。
2. 猫咪切换为“专注”动画（像素猫戴上小眼镜或眼睛变半闭，保持不动）。
3. 工具栏番茄图标变为红色倒计时数字（如 `24:59`）。
4. 专注阶段，久坐检测 `SedentaryMonitor` 收到 `POMODORO_START` 事件，暂停自身计时。
5. 专注结束：
   - 猫咪恢复 `idle`，弹出一条轻量通知：“番茄钟结束，休息5分钟吧~”。
   - `PomodoroManager` 自动进入休息阶段，倒计时显示绿色。
   - 通知按钮：【开始休息】【跳过休息】。
6. 休息阶段结束：
   - 通知：“休息结束，要开始下一个番茄吗？” 按钮：【开始】【稍后】。
   - 若用户未操作，5分钟后自动提示一次，随后不再打扰。
7. 若用户在专注阶段手动暂停，记录当前进度，可恢复或放弃。

**与久坐提醒联动**：
- 番茄钟专注期间，久坐计时器暂停。专注结束后，久坐计时器重置（因为已经提醒休息）。
- 如果用户跳过休息直接开始下一个番茄，久坐计时器继续累计，若超过阈值仍会触发久坐提醒（优先级低于番茄钟休息提醒）。

#### 5.4 UI呈现
- **工具栏番茄图标**：扁平线条，正常状态为空心橙线 `#FF6B35`；运行中填充实心橙并显示倒计时文本。
- **通知气泡**：番茄钟结束或休息结束时弹出，按钮采用填充风格。
- **设置面板**：两个滑块 + 长休息间隔输入框。

#### 5.5 事件
- `POMODORO_START`：携带时长，`SedentaryMonitor` 订阅。
- `POMODORO_END`：携带阶段（专注/休息），通知管理器订阅。
- `POMODORO_PAUSE/RESUME/CANCEL`：用于状态同步。

#### 5.6 实现模块
- `modules/pomodoro.py`：核心定时器、状态机。
- 修改 `modules/health/sedentary_monitor.py`：增加对番茄事件的响应。
- 修改 `ui/chat_bubble.py`：工具栏按钮、倒计时显示。
- 修改 `ui/settings_window.py`：健康页增加配置。

### 6. 习惯孵化

#### 6.1 功能概述
用户可设定希望养成的习惯（如“每天阅读30分钟”），桌宠每日在指定时间提醒，用户确认完成打卡，连续打卡天数形成 streak，猫咪给予鼓励。

#### 6.2 触发与交互

**创建习惯**
- 对话输入：“我要养成每天阅读30分钟的习惯，晚上9点提醒”。
- `HabitManager` 解析习惯名称、目标时间（可省略具体分钟，默认整点）、提醒时间。
- 生成确认卡片：“📋 习惯：阅读30分钟 | 提醒：每天21:00”，附带【确认】【修改时间】按钮。
- 也可在设置面板“习惯”页手动创建：输入名称、选择时间、勾选是否启用。

**每日提醒**
1. APScheduler 在指定时间触发 `HABIT_REMINDER` 事件。
2. 通知管理器以优先级（低于备忘录，高于一般健康提醒）显示通知：
   - 图标：像素小旗帜。
   - 内容：“到阅读时间啦！今天坚持了XX天哦~”
   - 按钮：【已完成】【推迟10分钟】【今天请假】
3. 用户点击“已完成” → 打卡成功，streak +1，更新 `last_check_date = today`。
4. 点击“推迟” → 10分钟后再次提醒，最多推迟3次。
5. 点击“今天请假” → streak 中断，记录中断日期。

**打卡与统计**
- 连续打卡7天，触发猫咪 `happy` 动画+鼓励语：“连续一周都坚持了，太厉害了喵！”。
- 中断后首次打卡重置 streak 为1。
- 设置面板“习惯”页显示每个习惯的当前 streak、最长 streak、总打卡次数、日历热力图（可选，Beta后期）。

#### 6.3 UI
- **通知气泡**：与健康提醒风格统一，按钮用强调色。
- **设置面板-习惯页**：
  - 顶部按钮“新建习惯”。
  - 列表每项：习惯名称、提醒时间、当前连续天数（大号数字）、最长连续天数、开关按钮、编辑/删除图标。
  - 点击某项可查看详情：打卡日历（简单月视图，已完成天数标记橙色圆点）。

#### 6.4 数据库
```sql
CREATE TABLE habit (
    id TEXT PRIMARY KEY,
    name TEXT NOT NULL,
    target_time TIME NOT NULL,
    streak INTEGER DEFAULT 0,
    longest_streak INTEGER DEFAULT 0,
    total_completions INTEGER DEFAULT 0,
    last_check_date DATE,
    enabled BOOLEAN DEFAULT 1,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

#### 6.5 事件
- `HABIT_REMINDER`：携带 habit 对象，通知管理器订阅。
- `HABIT_COMPLETED`：携带 habit id、新 streak，可用于触发养成奖励。
- `HABIT_BROKEN`：streak 中断，可用于鼓励对话。

### 7. 喂食与养成系统

#### 7.1 功能概述
用户完成健康行为（按时喝水、活动休息、饮食记录等）可获得“猫粮”点数。积累点数用于解锁猫咪的像素配饰（围巾、帽子、眼镜等）或新毛色。这是对健康管理功能的游戏化正向激励。

#### 7.2 点数获取规则

| 行为 | 猫粮点数 | 每日上限 |
|------|---------|---------|
| 按时喝水（点击喝水按钮） | +1 | +10 |
| 完成活动休息 | +2 | +6 |
| 确认饮食推荐（或手动记录） | +2 | +6 |
| 完成日程提醒（标记完成） | +1 | +5 |
| 习惯打卡（完成习惯） | +3 | +9 |

- 点数即时增加，通过事件 `CAT_FOOD_CHANGED` 更新UI。
- 当日总量、累计总量存储于 `app_settings` 的 `cat_food_daily`、`cat_food_total`。

#### 7.3 解锁与装备系统

**可解锁物品分类**：
- **配饰**：像素围巾、小帽子、眼镜、蝴蝶结、小背包等（叠加在猫本体上）。
- **毛色**：橘色（默认）、黑白、灰色、三花、虎斑等（替换猫本体底色）。

**解锁条件**：
- 每个物品设置固定价格（如围巾 30 猫粮、帽子 50 猫粮）。
- 默认初始拥有：橘色毛色、无配饰。

**解锁流程**：
1. 设置面板“外观”页新增“养成商店”区域。
2. 以网格展示所有物品，每个物品显示像素图标、名称、价格。未解锁为灰色，已解锁为彩色。
3. 点击未解锁物品且猫粮足够 → 弹出确认：“确定花费 XX 猫粮解锁 [物品] 吗？”
4. 确认后扣除总猫粮，更新 `unlockables` 表，物品状态变为 unlocked。
5. 已解锁物品可点击“装备”，装备后猫咪动画实时更新（叠加对应像素图层）。

#### 7.4 UI设计

**养成商店（设置面板-外观页内）**：
- 顶部显示当前猫粮数，图标 + 数值（如 `🍪 128`）。
- 下方分标签页：`配饰` | `毛色`。
- 网格每项为圆形浅灰底（`#F5F5F5`），中心显示物品像素图（48x48），下方名称和价格。
- 装备中的物品带橙色对勾标记。
- 点击已解锁未装备 → 装备；点击未解锁 → 购买确认弹窗。

**猫咪动画叠加**：
- 在 `FloatingPet` 渲染时，先绘制基础毛色，再依次绘制已装备配饰的像素图层（顺序：底层毛色 → 身体 → 配饰层）。
- 配饰层也有对应的像素帧，跟随猫的动作状态切换（如待机、开心等），因此美术资源需要按状态分别提供配饰的图层帧，或者简单配饰不跟随动作变化（仅附着在固定位置）。

**点数获取反馈**：
- 每次获得猫粮时，猫咪头顶短暂飘出 `+1` 或 `+2` 的像素文字动画（淡入上飘200ms消失），增加即时满足感。

#### 7.5 数据库
```sql
CREATE TABLE unlockables (
    id TEXT PRIMARY KEY,
    name TEXT NOT NULL,
    type TEXT NOT NULL,  -- 'accessory' | 'color'
    price INTEGER DEFAULT 10,
    unlocked BOOLEAN DEFAULT 0,
    equipped BOOLEAN DEFAULT 0
);
```
- `app_settings` 新增键：`cat_food_total` (INTEGER), `cat_food_daily` (INTEGER), `cat_food_date` (TEXT, 用于重置日限额)。

#### 7.6 事件
- `CAT_FOOD_CHANGED`：携带 `{ total, daily, delta }`，UI更新商店猫粮数。
- `ITEM_UNLOCKED`：携带物品id和名称，可用于通知或特殊动画。
- `ITEM_EQUIPPED`：携带物品id，猫咪重绘。

#### 7.7 实现模块
- `modules/feeding.py`：点数管理、解锁逻辑。
- 修改各健康管理模块（`drink_reminder`, `sedentary_monitor`, `meal_engine`, `habit.py`）：在确认行为时调用 `FeedingManager.add_food(amount, reason)`。
- 修改 `ui/settings_window.py`：外观页增加商店UI。
- 修改 `ui/floating_pet.py` 或动画控制器：支持配饰图层叠加。

### 9. 交互流程汇总图

```
用户行为 → EventBus → 业务模块 → 数据层
    ↓                      ↓
NotificationManager ←── 事件订阅
    ↓
猫咪动画 + 通知气泡 / 对话气泡
```

**各功能事件流**：
- 问候：唤醒 → Greeting.check() → 收集上下文 → LLM生成 → `GREETING_TRIGGERED` → 通知或对话显示
- 日记：定时/手动 → Diary.generate() → 聚合数据 → LLM生成 → `DIARY_GENERATED` → 存储 → 可选通知
- 彩蛋：消息 → EasterEgg.match() → 命中 → `PLAY_SPECIAL_ANIMATION` → 预设回复
- 备忘录：输入解析 → Memo.create() → APScheduler注册 → 到期 `MEMO_REMINDER` → 通知
- 番茄钟：启动 → Pomodoro.start() → `POMODORO_START` → 久坐暂停 → 结束 `POMODORO_END` → 通知
- 习惯：定时 → Habit.remind() → `HABIT_REMINDER` → 通知 → 确认打卡 → streak更新 → `HABIT_COMPLETED`
- 养成：健康行为确认 → Feeding.add_food() → `CAT_FOOD_CHANGED` → UI更新猫粮数
