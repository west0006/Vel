## 一、定位与范围

| 项 | 内容 |
|---|---|
| **是什么** | Vel 桌宠的**开发全量档案** —— 从设计定稿 → 方案拆解 → 落地实现 → 回归验证 |
| **当前阶段** | Alpha v0.1.0-alpha：核心服务与业务模块骨架已跑通，单元测试 42 项全绿 |
| **读者** | 开发者本人 · 后续接手人 · AI Agent（Agent 必须先读本文件，再读 `CURRENT-STATUS.md`） |

### ★ 如何扩展（结构约定）

本目录**按文档性质平行分层**。新增内容时按下表归入，**换主题只换文件名前缀，结构不变**：

| 要新增的内容 | 放哪 | 命名 |
|---|---|---|
| 权威设计（长期有效、会被反复引用） | `reference/` | `设计-<主题>.md` |
| 实施方案 / 待决方案 | `dev/` | `方案-<主题>.md` |
| 计划与待办清单 | `dev/` | `计划-<主题>.md` |
| 当日执行记录 | `dev/日志/` | `YYYY-MM-DD.md`（**同日追加同一文件，不新建**） |
| 外部工具 / 技术调研 | `knowledge/` | `调研-<主题>.md`；按日期的调研用 `YYYY-MM-DD-<主题>.md` |
| 缺陷记录 | **一律合入** `testing/buglist.md` | **不新建文件**（约定 4） |
| 被取代的旧文档 | `归档/` | 必须先登记进 `归档/README-归档说明.md` |
| 对话存档 | `历史对话/` | `N.txt` |

## 四、维护约定

1. **`reference/` 是权威层**：只放长期有效的结论。改动其中任何文件都必须在文件内留修订记录（版本号 + 日期 + 改了什么），设计层面的变更须先与用户确认。
2. **`CURRENT-STATUS.md` 必须随重大改动同步更新** —— 完成一个待办项、改变一个技术决策、出现一个新的阻塞，都要写进去。
3. **按日期的文件同日追加，不新建**：`dev/日志/YYYY-MM-DD.md`、按日期的 `knowledge/` 调研文件。
4. **台账类一律合入既有文件**：缺陷进 `testing/buglist.md`，不新建单文件。
5. **归档不删除**：被取代的旧文档移入 `归档/`，并在 `归档/README-归档说明.md` 登记版本链与取代关系，归档件开头标注「⚠️ 已作废，不要据以开发」。
6. **不要在 `doc/` 放二进制大件**（图片、模型、exe）；需要引用素材时写路径。
7. **文档与代码的一致性由 Agent 负责**：Agent 每次任务开始前读 `README.md` + `CURRENT-STATUS.md`，任务结束前把结论沉淀到对应层，不允许只改代码不更新文档。
